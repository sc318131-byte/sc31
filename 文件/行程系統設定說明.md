# 董事長行程系統：設定說明

網頁：<https://sc318131-byte.github.io/sc31/schedule.html>

這套系統由三個部分組成：

| 部分 | 檔案 | 做什麼 |
|---|---|---|
| 日曆網頁 | `schedule.html`、`schedule.js`、`schedule.css` | 不用登入就能查看；輸入共用通行碼後可新增、修改、刪除行程 |
| 資料庫 | `supabase/schedule.sql`、`supabase/schedule-passcode.sql` | 行程資料表；任何人可讀取，寫入要通過資料庫端的通行碼檢查 |
| LINE 提醒 | `supabase/functions/line-reminder/index.ts`、`supabase/cron.sql` | 每 5 分鐘檢查一次，行程開始前用 LINE 推播給管理者 |
| LINE 綁定 | `supabase/functions/line-webhook/index.ts`、`supabase/line-admin.sql` | 管理者傳「綁定 <綁定碼>」給官方帳號，自動記下他的 userId |

照下面的順序做一次就能啟用。**所有金鑰和密碼都只存在 LINE 與 Supabase 後台，不要寫進儲存庫裡的任何檔案。**

> **行程是公開的。** 網頁不用登入，知道網址的人都看得到行程名稱、時間、地點、備註和回報說明。不能公開的內容不要寫進行程。

---

## 一、準備 LINE 官方帳號

LINE Notify 已在 2025 年 3 月停止服務，所以改用 LINE 官方帳號的 Messaging API 推播。

1. 登入 [LINE Official Account Manager](https://manager.line.biz/)，建立一個官方帳號（例如「董事長行程提醒」）；已有官方帳號可直接使用。
2. 在官方帳號的「設定 → Messaging API」按「啟用 Messaging API」，選擇或建立一個提供者（Provider）。
3. 到 [LINE Developers Console](https://developers.line.biz/console/)，打開剛才的 Messaging API channel：
   - **Basic settings** 分頁：複製「Channel secret」（驗證 Webhook 用）。
   - **Messaging API** 分頁最下方的「Channel access token」按「Issue」，複製產生的權杖。
   - 同一頁有 QR code，**管理者要用手機掃描、把官方帳號加為好友**，否則收不到推播。
4. 到官方帳號的「設定 → 回應設定」：關閉「自動回應訊息」，並開啟「Webhook」。

> 管理者的 userId 不用手動抄，第四步部署 Webhook 後，管理者傳「綁定 <綁定碼>」給官方帳號就會自動記下。收通知的人不必是建立 channel 的帳號。
>
> 免費方案每月可推播的則數有上限，以 LINE 官方公告為準。每筆行程只會推播一次。

## 二、建立資料表

1. 打開 Supabase 專案的 **SQL Editor**。
2. 貼上 `supabase/schedule.sql` 的全部內容，按 Run。

> 之前已經執行過舊版（需要登入）的 `schedule.sql`，改貼上 `supabase/schedule-public-read.sql` 執行即可。現有行程會保留，登入用的名單與權限會移除。

3. 再貼上 `supabase/schedule-passcode.sql` 的全部內容，按 Run。這一步加入網頁編輯功能。
4. 另外執行下面這一行設定通行碼（換成你要的通行碼，至少 8 個字元，建議混合英文與數字）：

   ```sql
   select private.set_schedule_passcode('換成你的通行碼');
   ```

   通行碼不要寫進任何檔案。要更換時再執行一次，舊通行碼立即失效。

## 三、新增與修改行程

### 在網頁上（建議）

1. 打開日曆網頁，按「新增行程」，或點日曆上的日期；要修改時，點行程後按「編輯」。
2. 第一次會要求輸入通行碼。輸入一次後，同一個分頁不用再輸入；勾選「在這台裝置記住通行碼」則下次開啟也不用輸入。
3. 用公用電腦時不要勾選記住，用完按「已解鎖編輯」旁的「鎖定」。

通行碼在資料庫端檢查。**15 分鐘內錯誤 10 次，所有人的編輯會暫停 15 分鐘**，查看不受影響。要立即解除，在 SQL Editor 執行：

```sql
delete from private.schedule_passcode_failures;
```

### 在 Supabase 後台

1. **Table Editor → chairman_events**。
2. 新增：按「Insert → Insert row」，填寫後按 Save。
3. 修改：點兩下儲存格直接改；刪除：勾選該列後按 Delete。

| 欄位 | 填法 |
|---|---|
| `title` | 行程名稱（必填） |
| `start_at` | 開始時間（必填），例如 `2026-11-20 14:00:00+08`。結尾的 `+08` 代表台灣時間 |
| `end_at` | 結束時間，可留空 |
| `location`、`note` | 地點、備註，可留空 |
| `status` | `預定`、`已完成`、`已取消` 三選一，預設 `預定` |
| `report` | 回報說明，行程結束後填寫 |
| `remind_minutes` | 開始前幾分鐘用 LINE 提醒，例如 `30`、`60`、`1440`（一天）；留空為不提醒 |

`id`、`reminded_at`、`created_at`、`updated_at` 由系統自動填寫，不用動。

## 四、部署 LINE 提醒功能

### 4-1 設定 secrets

到 **Edge Functions → Secrets**（或 Project Settings → Edge Functions），新增四個：

| 名稱 | 值 |
|---|---|
| `LINE_CHANNEL_ACCESS_TOKEN` | 第一步複製的 Channel access token |
| `LINE_CHANNEL_SECRET` | 第一步複製的 Channel secret |
| `LINE_BIND_CODE` | 自訂的綁定碼，至少 8 個字元（例如 `a8Kq2mZ7pX4r`），只告訴管理者 |
| `CRON_SECRET` | 自己產生的一長串亂數，例如在終端機執行 `openssl rand -hex 32` |

`CRON_SECRET` 等一下第五步還會用到，先記在安全的地方。

> 已經知道管理者 userId 的話，也可以另外設定 `LINE_ADMIN_USER_ID`；有綁定時會優先使用綁定的 userId。

### 4-2 建立綁定用的資料表

在 SQL Editor 貼上 `supabase/line-admin.sql` 的全部內容，按 Run（可重複執行）。

### 4-3 部署兩個 Edge Function

**方法 A：用網頁後台（最簡單）**

依序部署 `line-reminder` 和 `line-webhook`，每個都要：

1. **Edge Functions → Deploy a new function → Via Editor**。
2. 名稱填 `line-reminder`（或 `line-webhook`）。
3. 把 `supabase/functions/line-reminder/index.ts`（或 `supabase/functions/line-webhook/index.ts`）的內容整份貼上，按 Deploy。
4. 部署後進入這個 function 的 **Details / Settings**，把「Verify JWT」（Enforce JWT verification）**關閉**。`line-reminder` 用 `CRON_SECRET` 驗證，`line-webhook` 用 LINE 的簽章驗證，兩個都不用 Supabase 的登入權杖。

**方法 B：用 Supabase CLI**

```bash
supabase login
```

```bash
supabase link --project-ref mqhowhmojncjpbfvovdv
```

```bash
supabase functions deploy line-reminder --no-verify-jwt
```

```bash
supabase functions deploy line-webhook --no-verify-jwt
```

### 4-4 設定 LINE Webhook 並綁定管理者

1. LINE Developers Console → 該 channel → **Messaging API** 分頁 → **Webhook settings**：
   - **Webhook URL** 填 `line-webhook` 的 **Endpoint URL**（在 Supabase 該 function 的 Details 頁複製）。用 CLI 部署時是 `https://mqhowhmojncjpbfvovdv.supabase.co/functions/v1/line-webhook`；用網頁後台 Via Editor 部署時，網址結尾可能是自動產生的名稱（例如 `clever-service`），以 Details 頁顯示的為準。按 Update。
   - 按 **Verify**，出現 Success 才算成功。
   - 開啟 **Use webhook**。
2. 管理者用手機在官方帳號的聊天室傳：

   ```
   綁定 a8Kq2mZ7pX4r
   ```

   （把 `a8Kq2mZ7pX4r` 換成 4-1 設定的 `LINE_BIND_CODE`）
3. 官方帳號回覆「綁定成功！之後董事長行程的提醒會傳到這個 LINE。」就完成了。

要換接收的人：新的人加好友後傳同樣的綁定訊息，就會取代舊的。查看目前綁定的人：`select * from private.line_admin;`。

| Verify 或綁定時的狀況 | 原因 |
|---|---|
| Verify 失敗，狀態 401 | `LINE_CHANNEL_SECRET` 不對 |
| Verify 失敗，狀態 500 | 有 secret 沒設定，或 `LINE_BIND_CODE` 少於 8 個字元；詳細原因在該 function 的 **Logs** |
| Verify 失敗，狀態 401 且 Logs 沒有紀錄 | 「Verify JWT」沒有關閉 |
| Verify 失敗，狀態 404 | 網址結尾和 function 的實際網址代號不同，改貼 Details 頁的 Endpoint URL |
| Verify 顯示逾時 | function 冷啟動較慢，再按幾次 Verify；請確認部署的是最新版 `line-webhook`（不載入 supabase-js，啟動較快） |
| 傳綁定訊息沒有任何回覆 | 沒開啟 Use webhook，或訊息不是以「綁定」開頭 |
| 回覆「綁定碼不正確」 | 綁定碼和 `LINE_BIND_CODE` 不一致 |
| 回覆「綁定失敗…line-admin.sql」 | 還沒執行 4-2 的 `supabase/line-admin.sql` |

## 五、啟用每 5 分鐘的排程

1. **Database → Extensions**，啟用 `pg_cron` 和 `pg_net`。
2. 打開 `supabase/cron.sql`，在 SQL Editor 貼上後，**只在編輯器裡**替換兩個地方，不要改回儲存庫的檔案：
   - `<專案代號>` 換成 `mqhowhmojncjpbfvovdv`；如果 `line-reminder` 的 Endpoint URL 結尾不是 `line-reminder`，把整段網址換成 Details 頁顯示的 Endpoint URL
   - `<CRON_SECRET>` 換成 4-1 設定的同一串亂數
3. 按 Run。

## 六、測試

1. 打開 <https://sc318131-byte.github.io/sc31/schedule.html>，按「新增行程」並輸入通行碼。
2. 開始時間設在 15 分鐘後，「LINE 提醒」選「10 分鐘前」，按儲存，確認日曆上看得到這筆行程。
3. 等 5～10 分鐘，管理者的 LINE 應該會收到：

   ```
   【董事長行程提醒】10 分鐘後開始
   行程：測試行程
   時間：11/12（週四） 15:30
   地點：總公司 5F 會議室
   ```

4. 回到後台，那筆行程的 `reminded_at` 會填上發送時間。

沒收到的話，在 SQL Editor 查看排程與 function 的回應：

```sql
select status, return_message, start_time from cron.job_run_details order by start_time desc limit 10;
select status_code, content, created from net._http_response order by created desc limit 10;
```

| 看到的訊息 | 原因 |
|---|---|
| `401 Unauthorized` | `cron.sql` 裡的密碼和 secrets 的 `CRON_SECRET` 不一致 |
| `缺少環境變數 …` | 4-1 的 secrets 沒設好 |
| `尚未設定接收者…` | 管理者還沒完成 4-4 的綁定 |
| `LINE 推播失敗 400` 或 `403` | 綁定的人封鎖了官方帳號，或 userId 錯誤；請重新綁定 |
| `LINE 推播失敗 401` | Channel access token 錯誤或已失效 |
| `LINE 推播失敗 429` | 本月推播則數已用完 |

## 網頁出現紅字時

| 紅字內容 | 原因與處理 |
|---|---|
| 「找不到行程資料表，請先在 Supabase 執行 supabase/schedule.sql」 | 還沒建立資料表。執行 `supabase/schedule.sql`。 |
| 執行 `schedule.sql` 出現 `relation "chairman_events" already exists` | 資料表已經存在，不要再執行 `schedule.sql`。改執行 `supabase/schedule-public-read.sql`（會保留現有行程）。 |
| 「資料庫還沒加入編輯功能，請先在 Supabase 執行 supabase/schedule-passcode.sql」 | 執行 `supabase/schedule-passcode.sql`，再執行 `select private.set_schedule_passcode('…');` 設定通行碼。 |
| 「管理者還沒設定通行碼」 | 執行 `select private.set_schedule_passcode('…');`。 |
| 「錯誤次數太多，編輯已暫停 15 分鐘」 | 等 15 分鐘，或執行 `delete from private.schedule_passcode_failures;` 立即解除。 |
| 「沒有權限…」 | 依序執行 `schedule-public-read.sql`（或新專案的 `schedule.sql`）與 `schedule-passcode.sql`。 |

執行完 SQL 後，網頁按「重新整理」或重新載入頁面即可。

## 提醒規則

- 只有狀態為「預定」、有設定提醒的行程會發送。改成「已完成」或「已取消」就不會再提醒。
- 每筆行程只提醒一次。修改**開始時間**或**提醒設定**後，會依新的時間再提醒一次。
- 排程每 5 分鐘執行一次，提醒可能比設定的時間晚最多 5 分鐘。訊息裡寫的是實際剩下的時間。
- 行程開始超過 10 分鐘後才建立的，不會補發。

## 安全須知

- 行程對外公開：任何人都能讀取行程的名稱、時間、地點、狀態、備註和回報說明，但看不到提醒設定。
- 網頁不能直接寫入資料表，只能透過檢查通行碼的函式新增、修改、刪除。通行碼只以雜湊存在資料庫的 private schema，網頁讀不到。
- 通行碼是大家共用的，無法追查是誰改的。有人離職或通行碼外流時，立刻用 `private.set_schedule_passcode` 更換。
- 勾選「記住通行碼」會把通行碼存在那台裝置的瀏覽器裡，只在自己的手機或電腦上勾選。
- Supabase 後台帳號仍能直接修改所有資料，請開啟兩步驟驗證。
- `config.js` 只能放 publishable key。LINE 權杖、`CRON_SECRET`、service_role 金鑰都只能放在 Supabase 後台。
- 權杖外流時：到 LINE Developers 重新產生 Channel access token，再更新 Supabase secrets。

## 安裝成手機 App（PWA）

報修登記和董事長行程都可以安裝到手機主畫面，開起來像一般 App，沒有網址列。兩個是分開的 App，圖示分別是藍色「修」和綠色「程」。

- **Android（Chrome）**：打開網頁，按頁面上方的「安裝 App」；沒有出現按鈕時，點右上角「⋮」→「安裝應用程式」或「加到主畫面」。
- **iPhone／iPad（Safari）**：點下方的「分享」→「加入主畫面」。一定要用 Safari 打開。
- **電腦（Chrome、Edge）**：網址列右側會出現安裝圖示。

離線時 App 仍然打得開，但看不到資料，連上網路後重新整理即可。行程資料不會存在手機的快取裡。
