# 董事長行程系統：設定說明

網頁：<https://sc318131-byte.github.io/sc31/schedule.html>

這套系統由三個部分組成：

| 部分 | 檔案 | 做什麼 |
|---|---|---|
| 日曆網頁 | `schedule.html`、`schedule.js`、`schedule.css` | 不用登入，打開就能查看行程與回報說明（只能看，不能改） |
| 資料庫 | `supabase/schedule.sql` | 行程資料表；任何人可讀取，只能在 Supabase 後台修改 |
| LINE 提醒 | `supabase/functions/line-reminder/index.ts`、`supabase/cron.sql` | 每 5 分鐘檢查一次，行程開始前用 LINE 推播給管理者 |

照下面的順序做一次就能啟用。**所有金鑰和密碼都只存在 LINE 與 Supabase 後台，不要寫進儲存庫裡的任何檔案。**

> **行程是公開的。** 網頁不用登入，知道網址的人都看得到行程名稱、時間、地點、備註和回報說明。不能公開的內容不要寫進行程。

---

## 一、準備 LINE 官方帳號

LINE Notify 已在 2025 年 3 月停止服務，所以改用 LINE 官方帳號的 Messaging API 推播。

1. 用**管理者本人**的 LINE 帳號登入 [LINE Official Account Manager](https://manager.line.biz/)，建立一個官方帳號（例如「董事長行程提醒」）。
2. 在官方帳號的「設定 → Messaging API」按「啟用 Messaging API」，選擇或建立一個提供者（Provider）。
3. 到 [LINE Developers Console](https://developers.line.biz/console/)，打開剛才的 Messaging API channel：
   - **Basic settings** 分頁最下方的「Your user ID」（U 開頭、33 碼）就是管理者的 LINE userId，記下來。
   - **Messaging API** 分頁最下方的「Channel access token」按「Issue」，複製產生的權杖。
   - 同一頁有 QR code，**管理者要用手機掃描、把官方帳號加為好友**，否則收不到推播。
4. 建議到官方帳號的「回應設定」關閉「自動回應訊息」，避免管理者回覆時收到罐頭訊息。

> 免費方案每月可推播的則數有上限，以 LINE 官方公告為準。每筆行程只會推播一次。
>
> 如果收通知的人不是建立 channel 的帳號，就無法從後台直接看到他的 userId，需要另外設定 Webhook 取得，請先聯絡開發者。

## 二、建立資料表

1. 打開 Supabase 專案的 **SQL Editor**。
2. 貼上 `supabase/schedule.sql` 的全部內容，按 Run。

> 之前已經執行過舊版（需要登入）的 `schedule.sql`，改貼上 `supabase/schedule-public-read.sql` 執行即可。現有行程會保留，登入用的名單與權限會移除。

## 三、新增與修改行程

網頁只能看，行程要在 Supabase 後台維護：

1. **Table Editor → chairman_events**。
2. 新增：按「Insert → Insert row」，填寫後按 Save。
3. 修改：點兩下儲存格直接改；刪除：勾選該列後按 Delete。

| 欄位 | 填法 |
|---|---|
| `title` | 行程名稱（必填） |
| `start_at` | 開始時間（必填），例如 `2026-11-20 14:00:00+08`。結尾的 `+08` 代表台灣時間 |
| `end_at` | 結束時間，可留空 |
| `location`、`note` | 地點、備註，可留空 |
| `status` | `預定`、`已完成`、`已取消` 三選一，預設 `預定` |
| `report` | 回報說明，行程結束後填寫 |
| `remind_minutes` | 開始前幾分鐘用 LINE 提醒，例如 `30`、`60`、`1440`（一天）；留空為不提醒 |

`id`、`reminded_at`、`created_at`、`updated_at` 由系統自動填寫，不用動。

## 四、部署 LINE 提醒功能

### 4-1 設定 secrets

到 **Edge Functions → Secrets**（或 Project Settings → Edge Functions），新增三個：

| 名稱 | 值 |
|---|---|
| `LINE_CHANNEL_ACCESS_TOKEN` | 第一步複製的 Channel access token |
| `LINE_ADMIN_USER_ID` | 第一步記下的 userId（U 開頭） |
| `CRON_SECRET` | 自己產生的一長串亂數，例如在終端機執行 `openssl rand -hex 32` |

`CRON_SECRET` 等一下第五步還會用到，先記在安全的地方。

### 4-2 部署 Edge Function

**方法 A：用網頁後台（最簡單）**

1. **Edge Functions → Deploy a new function → Via Editor**。
2. 名稱填 `line-reminder`。
3. 把 `supabase/functions/line-reminder/index.ts` 的內容整份貼上，按 Deploy。
4. 部署後進入這個 function 的 **Details / Settings**，把「Verify JWT」（Enforce JWT verification）**關閉**。這個 function 改用 `CRON_SECRET` 驗證，關閉後排程才呼叫得到。

**方法 B：用 Supabase CLI**

```bash
supabase login
```

```bash
supabase link --project-ref mqhowhmojncjpbfvovdv
```

```bash
supabase functions deploy line-reminder --no-verify-jwt
```

## 五、啟用每 5 分鐘的排程

1. **Database → Extensions**，啟用 `pg_cron` 和 `pg_net`。
2. 打開 `supabase/cron.sql`，在 SQL Editor 貼上後，**只在編輯器裡**替換兩個地方，不要改回儲存庫的檔案：
   - `<專案代號>` 換成 `mqhowhmojncjpbfvovdv`
   - `<CRON_SECRET>` 換成 4-1 設定的同一串亂數
3. 按 Run。

## 六、測試

1. 依第三步在後台新增一筆行程：`start_at` 設在 15 分鐘後，`remind_minutes` 填 `10`。
2. 打開 <https://sc318131-byte.github.io/sc31/schedule.html>，確認日曆上看得到這筆行程。
3. 等 5～10 分鐘，管理者的 LINE 應該會收到：

   ```
   【董事長行程提醒】10 分鐘後開始
   行程：測試行程
   時間：11/12（週四） 15:30
   地點：總公司 5F 會議室
   ```

4. 回到後台，那筆行程的 `reminded_at` 會填上發送時間。

沒收到的話，在 SQL Editor 查看排程與 function 的回應：

```sql
select status, return_message, start_time from cron.job_run_details order by start_time desc limit 10;
select status_code, content, created from net._http_response order by created desc limit 10;
```

| 看到的訊息 | 原因 |
|---|---|
| `401 Unauthorized` | `cron.sql` 裡的密碼和 secrets 的 `CRON_SECRET` 不一致 |
| `缺少環境變數 …` | 4-1 的 secrets 沒設好 |
| `LINE 推播失敗 400` 或 `403` | userId 錯誤，或管理者還沒把官方帳號加為好友 |
| `LINE 推播失敗 401` | Channel access token 錯誤或已失效 |
| `LINE 推播失敗 429` | 本月推播則數已用完 |

## 提醒規則

- 只有狀態為「預定」、有設定提醒的行程會發送。改成「已完成」或「已取消」就不會再提醒。
- 每筆行程只提醒一次。修改**開始時間**或**提醒設定**後，會依新的時間再提醒一次。
- 排程每 5 分鐘執行一次，提醒可能比設定的時間晚最多 5 分鐘。訊息裡寫的是實際剩下的時間。
- 行程開始超過 10 分鐘後才建立的，不會補發。

## 安全須知

- 行程對外公開：任何人都能讀取行程的名稱、時間、地點、狀態、備註和回報說明，但看不到提醒設定。
- 網頁和公開金鑰都無法新增、修改、刪除行程；只有能登入 Supabase 後台的人能改。後台帳號請開啟兩步驟驗證。
- `config.js` 只能放 publishable key。LINE 權杖、`CRON_SECRET`、service_role 金鑰都只能放在 Supabase 後台。
- 權杖外流時：到 LINE Developers 重新產生 Channel access token，再更新 Supabase secrets。

## 安裝成手機 App（PWA）

報修登記和董事長行程都可以安裝到手機主畫面，開起來像一般 App，沒有網址列。兩個是分開的 App，圖示分別是藍色「修」和綠色「程」。

- **Android（Chrome）**：打開網頁，按頁面上方的「安裝 App」；沒有出現按鈕時，點右上角「⋮」→「安裝應用程式」或「加到主畫面」。
- **iPhone／iPad（Safari）**：點下方的「分享」→「加入主畫面」。一定要用 Safari 打開。
- **電腦（Chrome、Edge）**：網址列右側會出現安裝圖示。

離線時 App 仍然打得開，但看不到資料，連上網路後重新整理即可。行程資料不會存在手機的快取裡。
